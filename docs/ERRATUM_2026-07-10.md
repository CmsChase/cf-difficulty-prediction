# Public Erratum and Research-Governance Reset

Date issued: 2026-07-10

This notice applies to the historical results and narrative in repository tags
`v1.0` through `v2.0`, including the committed v4, v5, and v6 papers. The
historical files and Git tags are retained unchanged as an audit trail.

## What was wrong

Two independent governance problems were found during a code-and-artifact
audit.

1. The checked-in experiment configuration used nested keys and declared an
   80/10/10 contest-grouped split and a 70/10/20 forward-time split. The old
   loader did not consume those nested split keys and silently used its
   70/15/15 defaults for both strategies. Therefore, historical artifacts that
   describe the declared ratios do not accurately describe the splits that the
   code actually generated. `configs/experiment_legacy_v6.yaml` records the
   effective historical ratios for audit purposes.
2. Several result-building modules ranked models or feature settings using
   held-out test MAE. This affected the main model analysis and some statement,
   semantic, robustness, ablation, and exposure summaries. The model-fitting
   functions inspected in this audit fit estimators on training rows, and the
   audit did not find test targets passed directly to estimator fitting.
   Nevertheless, choosing a reported winner after observing test performance is
   test-set reuse and can make the selected result optimistic.

Because the historical test results were viewed repeatedly across releases,
they cannot be made independent again by renaming them or by changing the
ranking code after the fact.

## How historical claims should now be read

- All pre-erratum test numbers are **retrospective held-out evaluations**, not
  confirmatory evidence from an unseen final test set.
- The old numerical tables and PDFs remain useful for code auditing,
  hypothesis generation, and descriptive comparison, but should not be cited
  as prospective validation.
- This erratum does not assert that every historical numerical value is
  incorrect. It says that the split description was wrong and the model/feature
  selection procedure did not support the strength of the original
  confirmatory wording.
- No corrected headline numbers are supplied in this notice. A corrected rerun
  must regenerate features, both splits, models, selection reports, figures,
  and paper tables from one recorded configuration fingerprint.

## Corrective controls introduced

- `configs/experiment.yaml` now has a versioned schema. Unknown keys, missing
  required sections, invalid values, and missing config files fail loudly.
- Feature, split, EDA, and analysis artifacts record the SHA-256 fingerprint of
  the effective configuration.
- Shared model-selection code selects candidates only on validation MAE and
  joins the already selected candidate to its test metrics. Regression tests
  deliberately make the validation winner different from the test winner.
- Test-only exposure comparisons no longer publish a winner and are labeled
  exploratory/descriptive.
- Historical generated outputs are not silently overwritten by this code-only
  governance change.

## Next confirmatory step

Independent evidence requires a separately reviewed prospective protocol and a
genuinely future cohort. That workflow is intentionally not treated as active
until its input capture, frozen prediction, public commitment, and later reveal
steps have passed an end-to-end dry run. Historical rows will not be backfilled
and described as prospective evidence.
